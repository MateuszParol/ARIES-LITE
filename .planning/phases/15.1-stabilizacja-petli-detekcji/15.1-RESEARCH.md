## Summary

Faza 15.1 wprowadza trzy ortogonalne ulepszenia petli `MozgRPi._petla_glowna()`:
(1) DNN skip-frames redukuje liczbe kosztownych forward pass na RPi4 bez tracenia sledzenia bbox,
(2) histereza stanow SKANOWANIE/SLEDZENIE zapobiega migotaniu trybu TX przy chwilowych brakach detekcji,
(3) `cv2.imshow` z `cv2.resize` powiekszy okno HUD 320x240 do czytelnego rozmiaru.

Caly stan stabilizacji enkapsulowany jest w nowej klasie `StabilizatorStanow` (`src/vision/stabilizator.py`), co izoluje logike od petli glownej i ulatwia testowanie. `brain.py` otrzymuje minimalne modyfikacje: import nowej klasy, wywolanie `stabilizator.aktualizuj(bbox)` zamiast bezposredniego `if bbox is not None`, oraz `cv2.resize` przed `imshow` w `_rysuj_hud()`.

**Primary recommendation:** Uzyc hybrydowego mechanizmu histerezy: licznik `_klatki_bez_twarzy` (lost count 10-15 klatek) jako brama do zmiany stanu SLEDZENIE→SKANOWANIE, bez dodatkowego streak filtra wejscia (DNN ma wbudowany confidence >=0.5 + sticky tracking w WykrywaczTwarzy — streak bylby redundantny).

### Pattern 1: DNN Skip-Frames z Hold-Last-BBox

**What:** Licznik `_klatka_licznik` inkrementowany przy kazdym wywolaniu `wykryj()`. Forward pass DNN wykonywany tylko gdy `_klatka_licznik % DNN_SKIP_EVERY == 0`. Miedzy forward passami `_ostatni_bbox` trzymany bez zmiany ("hold last"). Licznik wrappuje sie naturalnie przez Python int.

**When to use:** Zawsze gdy FPS kamery > FPS jaki DNN moze obsluzyc — przy 320x240 i res10_300x300 na RPi4 DNN kosztuje ~30-50ms/klatke, kamera produkuje ~15-30 kl/s.

**Recommended DNN_SKIP_EVERY:** Na podstawie legacy test_tracker (`DNN_SKIP_EVERY=5` przy Picamera2 320x240 na RPi4) — rekomendacja: **5** jako punkt startowy, stala modulowa latwa do zmiany.

**Strategia hold vs skip TX:** Rekomendacja: **hold last bbox** dla SLEDZENIE klatek pomiedzy DNN. Petla nadal wysyla TX SLEDZENIE z ostatnim bbox — Arduino widzi ciagly ruch zamiast przerw. Skip TX bylby gorszy: Arduino watchdog odpala sie przy braku ramki >500ms, a hold bbox jest zalecanym wzorcem w legacy kodzie.

**Gdzie umiescic logike skip:** W `WykrywaczTwarzy.wykryj()` lub w `StabilizatorStanow`. Rekomendacja: W `WykrywaczTwarzy.wykryj()` — enkapsulacja DNN logiki pozostaje w detektorze (tak jak w legacy `DetekcjaTwarzy`). `StabilizatorStanow` dostaje wynik `bbox` (uwzgledniajacy hold) i zajmuje sie tylko histereza stanow.

Alternatywnie: skip moze byc tez modulowa stala `DNN_SKIP_EVERY` w `brain.py` z licznikiem w petli glownej — prostsze, ale miesza DNN logike z logika petli. Rekomendacja: trzymac w detektorze.

**Uwaga o modelu DNN:** `WykrywaczTwarzy` aktualnie nie ma skip-frames (`detector.py` — kazde wywolanie `wykryj()` robi pelny forward pass). Trzeba dodac `_klatka_licznik` i `_ostatni_bbox` do klasy lub jako logike w petli glownej z konstanta w `brain.py`.

```python
# Wzorzec z legacy (legacy/src/modes/test_tracker.py linia 192-219):
self._klatka_licznik += 1
if self._klatka_licznik % DNN_SKIP_EVERY == 0:
    # pelny forward pass DNN
    self._ostatni_bbox = None
    # ... detect ...
# Streak lub histereza na _ostatni_bbox
```

### Pattern 2: Histereza Stanow (lost count)

**What:** `StabilizatorStanow` trzyma aktualny stan (`SKANOWANIE`/`SLEDZENIE`) i licznik `_klatki_bez_twarzy`. Przy `bbox is not None`: resetuj licznik, wejdz w SLEDZENIE natychmiast. Przy `bbox is None`: inkrementuj licznik; zmiana na SKANOWANIE tylko gdy licznik >= `LOST_THRESHOLD`. To jest "one-sided hysteresis" — wejscie szybkie, wyjscie powolne.

**When to use:** Zawsze gdy zrodlo detekcji ma sporadyczne false negatives (chwilowe niewidocznosci twarzy). DNN confidence threshold 0.5 juz odrzuca slabe detekcje, wiec wejscie szybkie jest bezpieczne.

**Recommended LOST_THRESHOLD:** 10-15 klatek (D-04). Przy ~15 FPS: 10 klatek = ~670ms bufor, 15 klatek = ~1s. Rekomendacja: **`LOST_THRESHOLD = 12`** jako rozumny kompromis.

**Streak filter wejscia (D-07 — ocena):** Nie potrzebny. `WykrywaczTwarzy` ma juz `sticky tracking z 20% histereza` (detector.py). Dodatkowo `MIN_CONFIDENCE=0.5` odrzuca slabe detekcje. Streak wejscia (`STREAK_REQUIRED=3` z legacy) byl potrzebny w legacy bo HAAR produkuje wiecej false positives — DNN jest znacznie precyzyjniejszy. Rekomendacja: **nie implementowac streak filtra wejscia** — zbedny.

```python
# src/vision/stabilizator.py — rekomendowany wzorzec:
class StabilizatorStanow:
    TRYB_SKANOWANIE = "SKANOWANIE"
    TRYB_SLEDZENIE = "SLEDZENIE"

    def __init__(self, prog_utraty: int = 12) -> None:
        self._stan: str = self.TRYB_SKANOWANIE
        self._prog_utraty: int = prog_utraty
        self._klatki_bez_twarzy: int = 0

    @property
    def stan(self) -> str:
        return self._stan

    def aktualizuj(self, bbox_wykryty: bool) -> str:
        """Aktualizuje stan na podstawie obecnosci detekcji.
        Returns: aktualny stan (SKANOWANIE/SLEDZENIE)
        """
        if bbox_wykryty:
            self._klatki_bez_twarzy = 0
            self._stan = self.TRYB_SLEDZENIE
        else:
            self._klatki_bez_twarzy += 1
            if self._klatki_bez_twarzy >= self._prog_utraty:
                self._stan = self.TRYB_SKANOWANIE
        return self._stan
```

### Pattern 3: Resize Okna imshow

**What:** `cv2.resize(klatka, (nowa_szerokosc, nowa_wysokosc))` przed `cv2.imshow()`. Alternatywnie `cv2.namedWindow("...", cv2.WINDOW_NORMAL)` z recznym resizem okna przez uzytkownika.

**Recommended:** Stala `HUD_SCALE` w `brain.py` mnozona przez LORES rozdzielczosc 320x240. Rekomendacja: **`HUD_SCALE = 2`** (640x480) — czytelne na typowym monitorze, nie obciaza CPU znaczaco (resize w C++ na 320x240 jest tani).

Wzorzec:
```python
# Na gorze brain.py:
HUD_SCALE: int = 2  # mnoznik rozdzielczosci imshow (320*2=640, 240*2=480)

# W _rysuj_hud():
if not self._headless:
    try:
        klatka_hud = cv2.resize(
            klatka,
            (klatka.shape[1] * HUD_SCALE, klatka.shape[0] * HUD_SCALE),
            interpolation=cv2.INTER_NEAREST  # szybkie, bez aliasingu na malych klatkach
        )
        cv2.imshow("ARIES-LITE pi_brain", klatka_hud)
        cv2.waitKey(1)
    except cv2.error:
        self._headless = True
        ...
```

`cv2.INTER_NEAREST` zamiast `cv2.INTER_LINEAR` — przy 2x-3x powieszeniu pikseli daje ostrzejszy wynik dla debugowania, a jest szybszy.

### Anti-Patterns to Avoid

- **Bezposredni TX bez histerezy:** Kazda klatka bez bbox wysyla SKANOWANIE, powodujac migotanie servo co kilka klatek — eliminowane przez `StabilizatorStanow`.
- **Zbyt niski LOST_THRESHOLD (< 5 klatek):** Histereza nieskuteczna — chwilowe blysniecia braku detekcji nadal powoduja przelaczenia.
- **Streak wejscia z DNN:** Opoznia start sledzenia bez rzeczywistej korzysci (DNN jest juz precyzyjny) — nie implementowac.
- **`cv2.resize` bez INTER_NEAREST lub INTER_LINEAR:** Default INTER_LINEAR jest OK, ale INTER_NEAREST jest szybszy dla prostego debugowania.
- **Hold bbox bez limitu czasu:** Przy DNN_SKIP_EVERY=5 hold bbox jest maksymalnie przez 4 klatki — akceptowalny lag sledzenia ~130ms przy 30 FPS. Nie potrzeba dodatkowego timeout na hold.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Thread-safe licznik klatek | Mutex + custom atomic | Zwykly `int` w jednym watku | `_petla_glowna()` jest single-threaded — brak race condition |
| Async DNN | Thread pool, queue | Synchroniczny DNN + skip-frames | Latencja async jest gorsza niz skip przy 320x240 na RPi4 |
| State machine framework | Custom dispatcher | Prosta logika `if/elif` z licznikiem | Tylko 2 stany — overhead biblioteki nieuzasadniony |

## Common Pitfalls

### Pitfall 1: _ostatni_bbox Hold po zakonczeniu sledzenia

**What goes wrong:** Gdy DNN_SKIP_EVERY=5 i twarz znika po klatce N, klatki N+1..N+4 nadal zwracaja `_ostatni_bbox` z ostatnia pozycja, co trzyma stan SLEDZENIE przez te klatki — to jest ZAMIERZONE zachowanie (hold), ale logika histerezy musi byc odporna: licznik `_klatki_bez_twarzy` powinien rosnac tylko gdy DETECTOR zwroci `None` (co przy hold jest falszywe).

**Prevention:** Rozroznic: "detektor zwrocil nowa detekcje" vs "petla uzyla ostatniego hold bbox". Jesli `StabilizatorStanow.aktualizuj()` dostaje `bbox_wykryty=True` na podstawie hold, licznik `_klatki_bez_twarzy` sie nie inkrementuje — co jest POPRAWNE, bo trzymamy ostatnia pozycje intencjonalnie. Przelaczenie SLEDZENIE→SKANOWANIE bedzie sie liczyc od klatki gdy DETECTOR faktycznie zwrocil `None` po ostatnim hold.

**Warning signs:** Stan SLEDZENIE trzyma sie przez bardzo dlugo po odejsciu osoby — oznacza ze hold jest nieskoncony (brakuje resetu sticky w detektorze).

### Pitfall 2: Migotanie heartbeat vs stabilizator

**What goes wrong:** `WatekHeartbeat` wysyla co 200ms SKANOWANIE gdy brak TX. Jesli petla glowna wysyla SLEDZENIE co kilka klatek, heartbeat NIE powinien wchodzic. Ale jesli petla zacznie wysylac SKANOWANIE przez stabilizator, heartbeat moze "podwoic" wysylke SKANOWANIE.

**Prevention:** Heartbeat sprawdza `time.time() - self._czas_ref[0] >= HEARTBEAT_INTERVAL` — przy 15+ FPS petla zawsze odswiezy `_czas_ostatniej_tx` przed HEARTBEAT_INTERVAL, wiec heartbeat nie wystreli. Brak problemu przy normalnym FPS.

### Pitfall 3: DNN_SKIP_EVERY = 1 (brak skip)

**What goes wrong:** Stala pozostawiona na 1 = brak optymalizacji, maksymalne obciazenie CPU.

**Prevention:** Domyslna wartosc 5, zakres testowy 3-10. Komentarz przy stale.

### Pitfall 4: HUD_SCALE zbyt duze na malym ekranie

**What goes wrong:** HUD_SCALE=4 daje 1280x960 — moze przekroczyc rozdzielczosc monitora i przyslac okno poza krawedz ekranu.

**Prevention:** Stala HUD_SCALE z komentarzem "2 = 640x480, 3 = 960x720".
