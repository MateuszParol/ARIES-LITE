Flashowanie istniejacego firmware v2.1 na Uno R4 WiFi. Firmware NIE jest modyfikowany — tylko kompilacja i upload. Per D-01: arduino-cli na RPi4.

Krok 1: Sprawdz czy R4 WiFi jest widoczny:
```bash
arduino-cli board list
```
Oczekiwany wynik: `/dev/ttyACM0` z FQBN `arduino:renesas_uno:unor4wifi`. Jesli port to `/dev/ttyACM1` — uzyj tego portu w kolejnych krokach.

Krok 2: Sprawdz zainstalowane biblioteki (per D-02 — srodowisko juz gotowe, weryfikacja tylko):
```bash
arduino-cli lib list
```
Oczekiwane: Servo 1.3.0, LiquidCrystal 1.0.7, QuickPID 3.1.9. Jesli brak — zainstaluj brakujace:
```bash
arduino-cli lib install "QuickPID@3.1.9"
arduino-cli lib install "Servo@1.3.0"
arduino-cli lib install "LiquidCrystal@1.0.7"
```

Krok 3: Kompilacja (weryfikacja ze firmware dalej kompiluje sie na renesas):
```bash
arduino-cli compile --fqbn arduino:renesas_uno:unor4wifi /home/parolisko/ARIES-LITE/src/arduino/aries_controller/
```
Oczekiwany wynik: zero bledow, output ~24% flash i ~22% RAM.

Krok 4: Flash na R4 WiFi (per D-03: FQBN arduino:renesas_uno:unor4wifi):
```bash
arduino-cli upload --fqbn arduino:renesas_uno:unor4wifi --port /dev/ttyACM0 /home/parolisko/ARIES-LITE/src/arduino/aries_controller/
```
Jesli "Could not open serial port" — Pitfall 3: odczekaj 2-3s, sprawdz `arduino-cli board list` (port mogl sie zmienic na ACM1), sprobuj ponownie. Ostatecznosc: wcisnij RESET na R4 i powtorz upload.

Krok 5: Uruchom monitor serial aby potwierdzic bootowanie firmware:
```bash
arduino-cli monitor --port /dev/ttyACM0 --config baudrate=115200
```
Oczekiwane logi: output z setup() — bootscreen HMI, Soft Start, inicjalizacja PID. Zapisz output do logu. Zamknij monitor Ctrl+C.

UWAGA: Per Pitfall 1 — monitor MUSI byc zamkniety przed jakimkolwiek innym urzadzeniem korzystajacym z portu serial.

  <how-to-verify>
**TEST 1 — LCD Bootscreen (pasywny, tylko zasilanie USB):**
1. Odlacz zasilanie 6V serw (jesli podlaczone)
2. Podlacz Arduino R4 WiFi przez USB do RPi (lub zasilanie USB)
3. Obserwuj LCD 1602
4. Oczekiwany wynik: LCD wyswietla "ARIES-LITE" na wierszu 0 i "v2.1" na wierszu 1 przez ~2 sekundy, potem przechodzi do "BEZCZYNNOSC" (lub SKANOWANIE jesli watchdog odpali)
5. Wpisz: PASS lub FAIL + opis problemu

**TEST 2 — Serwa Soft Start + Skan (aktywny — wymaga 6V):**
1. Sprawdz polaczenia breadboard PRZED wlaczeniem zasilania serw (D-08: ostroznosc)
2. Podlacz zewnetrzny zasilacz 6V do serw MG-90S
3. Wlacz Arduino (USB + 6V)
4. Obserwuj serwa — Soft Start (rampa 1400->1500us) powinien byc plynny, brak szarpniecia
5. Po ~500ms watchdog przechodzi do SKANOWANIE — obserwuj skan sinusoidalny Lissajous
6. Pitfall 2: Trzymaj reke gotowa przy wtyczce zasilacza 6V — jesli kable sie zaplatuja, odlacz natychmiast
7. Wpisz: PASS lub FAIL + opis problemu

**TEST 3 — Buzzer (semi-aktywny):**
PRZED TESTEM — zweryfikuj typ buzzera:
- Podlacz buzzer bezposrednio do 5V i GND (bez Arduino)
- Wydaje dzwiek = AKTYWNY (Pitfall 4: moze przekroczyc 8mA limit pinu R4 — przeskocz test lub dodaj tranzystor NPN)
- Nie wydaje dzwieku = PASYWNY (bezpieczny na D8, firmware uzywa tone() ktore jest odpowiednie)

Jesli PASYWNY:
1. Podlacz buzzer na D8
2. Firmware przechodzi do SKANOWANIE po starcie
3. Wymus przejscie do SLEDZENIE (Test 5 w Plan 02 — lub send_heartbeat z ramka TRACK mode)
4. Oczekiwany wynik: krotki ton przy zmianie stanu
5. Jesli nie mozesz wymusic SLEDZENIE teraz — wpisz DEFERRED (przetestujemy w Plan 02 Test 5)

Wpisz: PASS, FAIL, lub DEFERRED dla kazdego testu.
