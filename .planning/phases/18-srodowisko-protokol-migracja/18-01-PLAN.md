Utworz katalog `.planning/protocol/` i plik `PROTOCOL_SPEC.md` z nastepujaca zawartoscia:

1. Naglowek: `# ARIES-LITE Serial Protocol v1.0` ze statusem `**Status:** LOCKED` i data zatwierdzenia `2026-03-30` (per D-01).

2. Sekcja "Ramka — 8 bajtow" — tabela z kolumnami: Offset, Nazwa, Typ, Kodowanie, Zakres, Opis. Dokladne wartosci (per D-01 do D-06):
   - Offset 0: `start`, uint8, staly `0xAA`, marker poczatku ramki
   - Offset 1: `mode`, uint8, `0=IDLE, 1=SCAN, 2=TRACK` (per D-03)
   - Offset 2-3: `error_x`, int16, little-endian, zakres `-160..+160 px` (per D-02, D-05)
   - Offset 4-5: `error_y`, int16, little-endian, zakres `-160..+160 px` (per D-02, D-05)
   - Offset 6: `face_size`, uint8, `percent*255/100`, zakres `0..255` (per D-04)
   - Offset 7: `checksum`, uint8, XOR bajtow 1-6 (BEZ start markera), zakres `0..255` (per D-06)

3. Sekcja "Obliczanie checksum" — wzor: `checksum = mode XOR error_x_lo XOR error_x_hi XOR error_y_lo XOR error_y_hi XOR face_size`. WAZNE: bajt 0 (0xAA) NIE wchodzi do checksumy.

4. Sekcja "Przyklad referencyjny (Python)" — uzyj `struct.pack('<BhhB', mode, error_x, error_y, face_size)` do payload, potem XOR loop, potem pelna ramka. Konkretny przyklad: mode=2 (TRACK), error_x=45, error_y=-12, face_size=128. Oblicz i wpisz oczekiwany checksum numerycznie (per D-05 — Python uzywa `struct.pack('<h', val)`).

5. Sekcja "Przyklad referencyjny (Arduino C)" — `uint8_t buf[8]; buf[0]=0xAA; ...` z manualnym parsowaniem little-endian: `int16_t error_x = buf[2] | (buf[3] << 8);`.

6. Sekcja "Tryby pracy" — tabela: wartosc uint8, nazwa, opis. 0=IDLE (brak akcji), 1=SCAN (skanowanie sinusoidalne), 2=TRACK (sledzenie twarzy PID).

7. Sekcja "Parametry transmisji" — baudrate: 115200, 8N1, DTR=False (per research — Leonardo nie resetuje sie przy polaczeniu).

8. Stopka: `*Specyfikacja zamknieta: 2026-03-30. Zmiany wymagaja aktualizacji wersji protokolu.*`

Caly dokument w jezyku polskim (komentarze i opisy). Kod (Python/C) po angielsku jak w konwencji projektu.
