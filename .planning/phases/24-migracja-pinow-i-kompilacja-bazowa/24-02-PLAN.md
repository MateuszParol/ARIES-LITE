  </read_first>
  <action>
Flash firmware v2.1 na Arduino Uno R4 WiFi podlaczone przez USB do RPi4:

```bash
arduino-cli upload --fqbn arduino:renesas_uno:unor4wifi --port /dev/ttyACM0 src/arduino/aries_controller/
```

Jesli port to nie /dev/ttyACM0, sprawdz:
```bash
arduino-cli board list
```

Po uplaodzie sprawdz Serial Monitor przez 5 sekund:
```bash
timeout 5 stty -F /dev/ttyACM0 115200 raw -echo && timeout 5 cat /dev/ttyACM0 | xxd | head -20
```

Jesli upload nie powiedzie sie (brak portu, permission denied), zglos blad — moze wymagac `sudo usermod -a -G dialout $USER` lub restart.
  </action>

Uzytkownik weryfikuje 5 testow sprzetowych na fizycznym Arduino Uno R4 WiFi z DataLogger Shield:

**Test 1: LCD Bootscreen (MIG-04)**
1. Wlacz zasilanie Arduino
2. Sprawdz LCD wiersz 0: powinno byc "ARIES-LITE v2.1"
3. Wiersz 1: "Inicjalizacja..."
4. Po 2 sekundach LCD powinno pokazac tryb + katy

**Test 2: Soft Start Serw (MIG-08)**
1. Przy wlaczeniu zasilania obserwuj serwa — nie powinny szarpnac
2. Serwa powinny plynnie dojsc do pozycji 90/90 (centrum) w ~1.5s
3. Brak restartu Arduino (LCD nie mignie/zniknie)

**Test 3: Servo Sweep (MIG-05)**
1. Otworz Serial Monitor lub wyslij ramki SKANOWANIE z RPi
2. Obserwuj skan Lissajous — serwa PAN (D6) i TILT (D9) powinny oscylowac plynnie
3. Brak jittera (tykania) lub nierownomiernego ruchu

**Test 4: Serial z RPi (MIG-07)**
1. Na RPi uruchom: `python3 -c "from src.vision.serial_interface import SerialInterface; s = SerialInterface(); s.open(); s.send_heartbeat(); s.close(); print('OK')"`
2. Powinno wypisac "OK" bez bledu
3. Arduino NIE powinno sie zresetowac przy otwarciu portu (brak ponownego bootscreen na LCD)

**Test 5: Stabilnosc zasilania (MIG-08)**
1. Wylacz zasilanie Arduino
2. Wlacz ponownie
3. Powtorz 5 razy
4. Zadne wlaczenie nie powinno spowodowac restartu podczas ruchu serw
